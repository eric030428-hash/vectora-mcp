# 공통 원칙

현재 사용자 지시가 최우선이다. 아래는 사용자가 정한 제작 규격과 그림을 성립시키는 원칙이며 평가원 공식 규정을 뜻하지 않는다. 유형별 예외는 해당 요소에만 적용한다.

## 인쇄·문자·편집

- 최종 전체 폭은 **108mm 이하**. 텍스트일러는 보통 108mm, 다른 그림은 용도에 맞는 폭을 정한다. 얼굴 하나를 최대 폭까지 늘리지 않는다.
- 모든 실질 문자·숫자·기호·제목·범례·출처는 **UND폰트v2.1 Regular 8pt, 자간 -6%**. 제목도 크기·가짜 굵게·임의 기울임 대신 위치와 여백으로 구별한다. 폰트가 없거나 문자가 지원되지 않으면 자동 대체하지 않는다.
- 새 그림은 별도 문서/대지에 만들고 기존 작업을 보존한다. 수정 요청은 지정된 그림·요소에만 적용한다.
- 편집 원본은 **`.vectora`로 저장**하고 같은 문서에서 JPEG를 내보낸다. **인물·삽화는 원화 이미지 개체로 포함해도 된다.** 그림은 위치·크기·교체가 가능하게 두고 문자·말풍선·수치 그래프·모식도는 별도 편집 요소로 유지한다. 전체 조판을 한 장의 이미지로 합치거나 문자를 전부 윤곽선으로 바꾼 것을 편집 원본으로 취급하지 않는다. 얼굴·원화 단품도 이미지 개체를 담은 `.vectora`와 JPEG로 전달한다. SVG와 원본 PNG는 필요할 때만 내부 작업 자료로 사용하며 기본 납품물에 추가하지 않는다. 원화 포함 파일을 순수 벡터라고 보고하지 않는다. 폰트 바이너리는 포함하지 않는다.
- 일반 규격선은 **0.3pt**: 모식도의 테두리·연결선, 대화 말풍선, 그래프 보조선·인출선·범례 테두리. 그래프의 축·개형·점선·6색 규칙은 그래프 문서에만 둔다. 인물·삽화·텍스트일러 장식의 모든 획에 이 굵기를 강제하지 않는다.
- 제공된 문장·밑줄·식별 기호·빈칸·수치·소수 자릿수·연결 의미를 유지한다. 빈칸의 답, 새 통계, 요청 없는 이름·제목·해설은 넣지 않는다. 제작 경위나 검사 결과는 그림 밖에 기록한다. 장면 내용인 ‘AI’와 ‘AI 생성’ 제작 표시는 구별한다.
- 제공된 단위·기준 시점은 적용되는 자료 가까이, 주석·출처는 해당 자료의 아래 여백에 둔다. 여러 자료의 단위나 출처를 섞지 않으며, 입력에 없는 기관명·연도·출처를 관행상 추가하지 않는다. 작은 보조 정보도 위 문자 규격을 유지한다.

## 선 색상

- 도형 윤곽·말풍선 몸통과 꼬리·모식도 연결선·화살표·그래프 축/개형/보조선/인출선·범례 테두리 등 **벡터 선은 순검정 `#000000`, 불투명도 100%**로 명시한다. 회색이나 검정에 가까운 색을 기본선으로 사용하지 않는다. 상위 그룹 투명도 때문에 선이 회색이 되는 것도 피한다. 채운 화살촉과 선처럼 쓰는 가는 채움 경로에도 적용한다. 선의 강약은 유형별 굵기·실선/파선으로 구분한다.
- **회색 채움 면·명암 면은 그대로 허용한다.** 검은 선 규칙을 면 전체를 검게 채우라는 뜻으로 해석하지 않는다. 원화 이미지 내부의 선·질감·음영은 해당 원화 화풍을 유지하며 픽셀을 검정으로 치환하지 않는다.
- 예외는 원화를 그대로 배치한 인물·삽화 내부 표현과, 텍스트일러에서 매체의 구조·작은 장식·접촉 그림자를 자연스럽게 표현하는 데 필요한 국소적인 회색 선이다. 텍스트일러도 기본 윤곽선은 검정이며, 장식 예외를 본문 틀이나 복합형 속 그래프·대화·모식도 전체에 확장하지 않는다. 예외의 요소와 디자인상 이유를 작업 기록에 남긴다.
- 최종 검수에서 벡터 개체의 선 색과 개체/상위 그룹의 유효 불투명도를 확인한다. 허용 예외 밖의 회색 선은 검정으로 고친다. JPEG의 가장자리 안티앨리어싱 픽셀은 회색 선 설정과 구별한다.

## 크기와 배치의 공통 계산

**본문 측정 또는 지정 텍스트 상자 예약 → 내용 영역 → 주변 요소 → 최종 외곽** 순으로 설계한다. 이전 그림의 종횡비를 선택하는 방식은 쓰지 않는다.

1. 실제 폰트와 자간으로 줄바꿈·줄높이를 측정한다. 글자 수나 다른 폰트의 평균 자폭으로 완료하지 않는다. 여는 괄호만 줄 끝에, 닫는 괄호·문장부호만 다음 줄에 남지 않게 한다.
2. `내용 틀 높이 = 조판 높이 + 위·아래 여백`. 제목·본문·작성자·삽화가 있으면 각각 공간을 예약한다. 글상자의 프레임, 보이는 글 획, 밑줄은 구분한다.
3. `다음 행 시작 = 현 행의 가장 아래 외곽 + 행간`. 현 행에는 몸통·꼬리·인물·이름·소품이 포함된다. 전체 그림 높이에 비례해 모든 y좌표를 일괄 늘리지 않는다.
4. 나란한 비교 요소는 같은 기준선·규칙적인 틈·일관된 크기를 가진다. 항목 내부의 간격보다 항목 사이 간격을 크게 해 묶음을 드러낸다. 글 분량이 다르면 필요한 폭과 높이를 조정하며 기계적인 등분·같은 높이에 집착하지 않는다.
5. 원은 1:1, 인물·사물은 자연스러운 종횡비를 유지한다. 인물 사이의 상대 크기는 **머리끼리** 비교하며 소품 포함 전체 높이로 얼굴을 맞추지 않는다.
6. 글·선의 물리 규격을 유지한 채 줄바꿈·영역 너비·높이·라벨 위치를 조정한다. 전체 Scale로 맞추거나 `textLength`로 글자를 압축하지 않는다. 지도는 문자·지시선을 추가하기 전에 지리 바탕만 비례 확대·축소하며 [지도 원칙](map-illustrations.md)을 따른다. 범례·이름·화살촉·꼬리·동작 궤적도 전체 외곽에 포함한다.

유형 문서의 수치 범위는 미지정 레이아웃의 **출발값**이다. 필수 규칙은 글/윤곽이 충돌하지 않고 묶음·대응·크기 관계가 읽히는 것이다. 범위에 맞추기 위해 내용이나 글 크기를 바꾸지 않는다. 새 배치가 요구되면 같은 원리로 계산하고 특정 매체·개수·포즈로 제한하지 않는다.

## 사용자가 텍스트 상자 크기를 지정한 경우

- ‘텍스트 상자 높이/너비’는 나중에 넣을 **내용 영역의 치수**다. 그림 전체·말풍선 외곽 크기나 여백을 포함한 크기로 해석하지 않는다. 사용자가 명시적으로 전체 그림/말풍선 크기를 지정한 경우와 구별한다.
- 지정한 치수 그대로의 예약 직사각형을 먼저 둔다. `안쪽 면 너비 ≥ 지정 너비 + 좌우 여백`, `안쪽 면 높이 ≥ 지정 높이 + 위아래 여백`으로 만들고 테두리·둥근 모서리·머리말·제본·장식·꼬리 등은 그 바깥에 더한다. 인물이 예약 공간을 차지하지 않게 한다. 높이만 지정했으면 너비는 해당 유형의 가용 폭으로 설계하며 누락된 치수를 임의의 사용자 요구로 기록하지 않는다.
- 높이 100mm의 텍스트 상자는 **100mm의 사용 가능한 빈 높이**를 보장한다. 위아래 여백을 2mm씩 선택했다면 내용 면은 최소 104mm이며 장식·말풍선 모서리 등은 별도다. 전체 그림을 100mm 높이에 맞추거나, 100mm 안에서 여백을 빼지 않는다. 108mm 제한은 전체 **너비**이며 높이 상한이 아니다.
- 본문이 아직 없으면 임시 문구·가짜 문장·요청하지 않은 입력용 테두리를 넣지 않고 비워 둔다. 예약 영역의 x/y/너비/높이는 제작 기록 또는 레이아웃 메타데이터에 남겨 실제 사용 영역을 확인할 수 있게 한다. 이 좌표·치수 표시는 그림 안에 출력하지 않는다.
- 본문도 함께 제공되면 지정 영역에 조판하되 원문·글 크기를 줄여 맞추지 않는다. 지정 치수·최대 너비·주변 필수 요소가 양립할 수 없는 경우에만 충돌하는 조건을 설명하고 조정을 확인한다. 본문이 없다는 이유만으로 제작을 멈추지 않는다.

## 사용자가 텍스트 줄 수를 지정한 경우

- ‘N줄이 들어갈 예정’이면 **UND폰트v2.1 Regular 8pt·자간 -6%로 정확히 N줄인 측정용 텍스트 상자**를 만들고 실제 높이를 측정한다. 단순히 `N × 8pt`로 높이를 추정하지 않는다. 글꼴 로딩·줄높이·첫 줄과 마지막 줄을 포함한 상자 높이를 반영한다.
- 너비는 사용자가 지정한 텍스트 상자 너비, 없으면 해당 유형의 가용 본문 폭을 사용한다. 행간도 사용자 지정값을 우선하고, 미지정이면 실제 제작에 쓸 기본 행간으로 측정하여 그 값을 기록한다. 측정 후 조판의 행간을 바꾸면 다시 측정한다.
- 본문이 없으면 짧은 한글 측정 문구를 **명시적 줄바꿈으로 N줄** 만든다. 자동 줄바꿈으로 N줄보다 늘지 않는지 확인하며 빈 문자열이나 줄바꿈만으로 측정하지 않는다. 실제 본문이 제공됐다면 그 문장으로 측정하고, 지정 너비에서 요구 줄 수와 다르면 본문을 바꾸거나 글자를 축소해 숨기지 않는다.
- 측정한 **텍스트 프레임 전체 높이**를 예약 높이로 사용한다. 글 획만의 경계나 첫 줄~마지막 줄 기준선 거리로 대체하지 않는다. 이 높이의 직사각형을 텍스트일러 중앙 또는 발표형 큰 말풍선 안에 두고, [지정 크기 계산](#사용자가-텍스트-상자-크기를-지정한-경우)처럼 사방 여백·장식·꼬리를 바깥에 더한다.
- 측정용 문구와 임시 상자는 최종 그림에 남기지 않고 빈 공간만 확보한다. 줄 수·측정 너비·폰트·행간·측정 높이는 그림 밖 제작 기록/레이아웃 메타데이터에 남긴다. 숨긴 측정 문자를 최종 SVG에 남기는 것도 피한다.
- 줄 수와 고정 높이를 함께 지정하면 실제 N줄 높이가 그 공간에 들어가는지 확인한다. 조건이 충돌할 때만 조정을 확인하고, 측정 실패나 대체 폰트 결과를 정확한 치수로 보고하지 않는다.

## 문자 안의 표식

- 밑줄은 조판된 문자열 구간에 붙이고 줄이 바뀌면 해당 줄의 실제 폭에 맞춰 나눈다. 빈칸 상자는 문장 순서와 기준선을 유지한다.
- 자료 식별 `(가)/(나)/(다)/(라)`의 UND 전용 입력은 각각 **`(!)/(@)/(#)/($)`**. 의미 이름과 실제 저장 문자열을 구별한다. 일반 문장까지 전역 치환하지 않는다.
- 글리프가 존재해도 뜻과 다른 그림으로 표시될 수 있다. 전용 기호·괄호·단위는 실제 모양을 확인한다. 폰트 환경과 기술적인 대체 처리는 실행 문서에 둔다.

## 결과 파일과 저장 위치

- **완성 일러스트 1개당 기본 최종 파일은 정확히 2개:** 동일한 파일명 본체의 `이름.vectora`와 `이름.jpeg`. 복합형의 각 구성 요소를 별도 납품 파일로 나누지 않는다. 여러 완성 일러스트를 요청하면 각각 한 쌍씩 만든다. 사용자가 다른 형식이나 추가 파일을 명시적으로 요청한 경우에만 그 요청을 반영한다.
- 파일명과 폴더는 각각 독립적으로 사용자 지정을 우선한다. 파일명 규칙·번호·띄어쓰기·대소문자를 보존하고 임의의 `final`, `preview`, `export` 접미사를 한 파일에만 붙이지 않는다. 확장자를 포함한 이름이면 확장자를 분리해 같은 본체를 두 파일에 사용한다. 기본 확장자는 `.jpeg`이며 사용자가 `.jpg`를 명시하면 JPEG 형식을 유지하고 그 확장자를 따른다.
- 저장 폴더를 지정하면 해당 폴더에 두 파일을 함께 저장한다. 상대 경로는 현재 작업 공간을 기준으로 해석하고 필요한 폴더를 만든다. 지정하지 않으면 **현재 작업 공간 바로 안**에 저장한다. 파일명만 없으면 내용·유형을 드러내는 적절한 이름을 정한다. 요청 없는 날짜 폴더나 `output/` 하위 폴더로 바꾸지 않는다.
- 기존의 무관한 파일을 덮어쓰지 않는다. 자동으로 정한 이름이 충돌하면 두 파일에 같은 번호를 붙인다. 사용자가 정확한 이름을 지정했고 교체 권한이 불명확하면 조용히 덮어쓰거나 이름을 바꾸지 않는다.
- 원본 PNG·중간 SVG·검수 이미지·생성 기록은 최종 두 파일과 구분된 임시 작업 영역에 보관하거나 문서 메타데이터에 기록한다. 사용자 저장 폴더에 추가 납품물처럼 나열하지 않는다. 기존 파일을 두 개로 맞추려고 삭제하지 않는다. 원화는 `.vectora`에 포함해 임시 경로 의존을 없앤다.
- **Vectora 저장 → 저장본 재열기·확인 → 같은 최종 문서의 JPEG 내보내기** 순서를 따른다. 스크린샷·PNG 이름 변경·별도 렌더러 변환으로 JPEG 내보내기를 대신하지 않는다. 자세한 실행은 [저장과 검증](vectora-contract.md#저장과-검증)을 따른다. 저장/내보내기 기능을 사용할 수 없으면 미완료 항목을 알리고 두 파일을 만들었다고 하지 않는다.
- 대화창에는 **내보내고 검수한 JPEG 자체를 이미지로 표시**하고 `.vectora` 다운로드 링크를 제공한다. 로컬 이미지 표시는 `![그림 설명](<JPEG의 절대 경로>)` 형식을 사용한다. PNG 원화·앱 화면·미리보기 이미지를 최종 JPEG 대신 표시하지 않는다.

## 공통 완료 검사

- 요청한 대상·문구·수치·관계가 모두 있고, 추가한 정답·예시의 문구가 없는가?
- 실제 렌더에서 글꼴·물리 크기·자간·대지 폭이 맞는가? 상위 그룹 변형으로 글자가 변형되지 않았는가?
- 글이 읽히고 여백이 일정하며 꼬리·이름·외부 라벨·중요한 동작이 잘리지 않는가? 겹친 경계 상자는 실제 윤곽과 의도에 따라 판단한다.
- 개체와 문자가 분리되어 수정 가능하고, 실행한 저장·재열기에서 형상과 속성이 보존되는가?
- 선은 허용 예외 밖에서 불투명 순검정인가? 복합형에 요청된 모든 유형의 문서를 읽고 각 요소에 적용했는가?
- 사용자 파일명·폴더를 지켰고 같은 이름의 `.vectora`와 JPEG가 실제로 저장되었는가? 대화창 이미지가 그 JPEG인가?

XML/폰트 검사 통과와 화풍·배치 검수는 별개다. 최종 인쇄 크기로 한 번, 세부가 보이는 크기로 한 번 확인한다.
